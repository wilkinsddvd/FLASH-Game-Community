### 2) 真机调试报错 —— 已定位并修复
- **错误（开发者工具日志里的原话）**：
  `task type:upload exec error  Error: invalid file: utils/request.js, 71:28` + `SyntaxError: Unexpected token ?`
  日志位置：`~/Library/Application Support/微信开发者工具/<hash>/WeappLog/logs/2026-09-12-00-54-02-346.log`（090:54 与 01:30 各报一次）；同一时段还有 `routeTo appLaunch timeout`（后果，不是原因）。
- **根因链**：
  1. `miniprogram/utils/request.ts:81` 写了 `resolve((res.data ?? null) as T)` —— **空值合并 `??` 是 ES2020 语法**；
  2. 项目根 `tsconfig.json` 里 `"target": "ES2020"` → 开发者工具内置的 **TypeScript 4.1.2** 按 ES2020 输出，`??` 原样保留；
  3. `project.config.json` 里 `"es6": false` → 开发者工具自己的 ES6→ES5 转换（babel）是关的，没人再降级；
  4. 真机调试/预览走的是**上传链路**，其代码包校验器只支持到 **ES2018** → 撞上 `?` 直接 SyntaxError → 上传/调试失败。
  模拟器不走该校验，所以“模拟器能跑、真机不行”。
- **修复**：`tsconfig.json` 的 `"target": "ES2020"` → **`"ES2017"`**（只动这一个字段）。ES2018+ 会降级（对象展开→`Object.assign`，`??`/`?.`→三元/条件），运行时用的都是真机支持的 API。
- **验证（用开发者工具自带的 TS 4.1.2 编译两次做对照，非常硬）**：
  - 修复前：`resolve((res.data ?? null));` → 按 ES2018 解析报 `Unexpected token 70:39`，与工具报的 `71:28` 对得上；
  - 修复后：`resolve(((_a = res.data) !== null && _a !== void 0 ? _a : null));` → **23 个产物文件在 ES2018 / ES2015 两级全部解析通过**。
  - 全工程扫描：`??` 只有这 1 处，`?.` / `||=` / `&&=` / `??=` / 可选 catch / 数字分隔符 均为 0 → 没有其它同类地雷。
- 用户需做：**重新编译（必要时 清缓存→全部清除）** 后再试真机调试。
- 经验：以后小程序的“编译不过/真机报错”先看 `WeappLog/logs/*.log`，再看 `WeappCache/WeappCompileCache/` 里**真正被使用的编译产物**（能直接确认缓存是否过期）。

### 2b) 真机调试仍报错的真正原因（01:39，已修）——**编译缓存不认 tsconfig**
- 上次改 `tsconfig.target` 没生效：01:38/01:39 两次报错行号仍是 `utils/request.js, 71:28`。
- **铁证（找到开发者工具的编译缓存）**：
  `~/Library/Application Support/微信开发者工具/<hash>/WeappCache/WeappCompileCache/<id>/caa04df063620424931e5a70bb9c4d2a`
  （mtime **00:54:07**）里赫然写着 `resolve(res.data ?? null);` → 01:38 的上传校验用的还是这份 **00:54 的旧产物**。
- **机制**：编译缓存的键 = `infoKey`（编译开关，如 `2_false_..._["typescript"]_{babelSetting}_false`）+ **源文件 mtimeMs**；**不含 tsconfig 的 hash/target** → 改 tsconfig 不触发重编。
- **最终修法（不依赖编译器脸色）**：把源码 `miniprogram/utils/request.ts` 里的 `res.data ?? null` 改成 ES5 三元写法（`res.data === undefined || res.data === null ? null : res.data`），注释也重写为不含 `?` 号字样。
  - 好处：源文件一变 → 缓存键变 → **一定会重新编译**；产物在任何 target 下都无 ES2020 语法。
- **验证（最坏情况假设：插件完全无视 tsconfig，target=ES2020）**：用开发者工具自带的 TS 4.1.2 编译 → 46 个产物文件按 **ES2018 级别全部解析通过**（ES2018 就是该校验器上限：原报错停在 71:28，而同一文件 58 行的对象展开它接受了）。
- 全工程扫描：源码里 `??`/`?.` 已为 **0 处**；无 `.js` 文件、无 `miniprogram_npm`、未引用第三方组件 → 无其他地雷。
- 待办：用户重编（保险起见 清缓存→全部清除）后重试；若再报错就再读日志。
- **教训（重要）**：小程序改编译配置（tsconfig / project.config.json）后，**必须清编译缓存**，否则旧产物会继续被复用、让你误以为“改了没用”。
