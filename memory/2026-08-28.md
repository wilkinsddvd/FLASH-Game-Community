# 2026-08-28

## 修复记忆索引（方案 C：本地 llama.cpp embedding）

用户发现 memory_search 不可用（"index metadata is missing"）。诊断链：
- 索引库为空 + 配置只配了 deepseek key，而 memorySearch 默认 provider 是 openai（无 key）→ CLI 启动即报 "No API key found for provider openai"
- 决定走方案 C：本地 GGUF embedding

踩坑记录：
1. `openclaw plugins install @openclaw/llama-cpp-provider` 的 npm install 被我自己的 180s timeout SIGKILL 了 → 后台重跑 npm install 完成
2. 插件注册要用 `openclaw plugins install ... --force`（node_modules 已存在时），manifest id 是 `llama-cpp`
3. 默认模型 `ggml-org/embeddinggemma-300m-qat-q8_0-GGUF` 从 huggingface.co 下载**被墙卡死**（10 分钟 0% CPU）→ 改用 **hf-mirror.com** 手动下载 313MB 到 `~/.openclaw/models/embeddinggemma-300m-qat-Q8_0.gguf`，并设 `agents.defaults.memorySearch.local.modelPath`
4. 被 kill 的 reindex 会留孤儿进程 + 死锁文件 `openclaw-agent.sqlite.reindex-lock.sqlite` → 杀进程 + 删锁文件后重跑 `openclaw memory index --force`
5. 网关侧生效必须重启 gateway（插件安装后未加载）

最终配置：
- `agents.defaults.memorySearch.provider = local`
- `agents.defaults.memorySearch.local.modelPath = ~/.openclaw/models/embeddinggemma-300m-qat-Q8_0.gguf`
- 17 chunks 已索引，会话内 memory_search 语义搜索验证通过

经验：国内网络 HuggingFace 直连不通，node-llama-cpp 类下载一律走 hf-mirror.com。
