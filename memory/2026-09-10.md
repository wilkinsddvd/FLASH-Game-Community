# 2026-09-10

## 排查：桌面/文档被 iCloud 云化（重要）

用户问「如何防止存储被 iCloud 云化」，查了本机实际状态，结论是**已经中招**：

### 事实
- `~` 桌面与文档同步开着：`~/Desktop`、`~/Documents` 都带
  `com.apple.file-provider-domain-id: com.apple.CloudDocs.iCloudDriveFileProvider/...`
  `~/Desktop` 还带 `com.apple.fileprovider.detached#B`；
  `~/Library/Mobile Documents/com~apple~CloudDocs/` 里只有 `Desktop`/`Documents` 两个软链指回本地。
- 「优化 Mac 存储」= 开（`defaults read com.apple.bird optimize-storage` → 1）。
- 桌面 220,935 个文件，逻辑 2.1GB，本地只占 302MB → 约 1.8GB 只在云端。
- 198,155 个文件是 dataless（空占位）：`find ~/Desktop -flags +dataless`。
- **读 dataless 文件直接报 EDEADLK (errno 11)**，`head`/普通程序读不了；`brctl download <path>` 能拉回来。
- FLASH 仓库里 49 个被抽干（`.idea/*`、`__pycache__/*.pyc`、`root_result.txt`、`media/inbound/*.png`、`FLASH_END_PRO/api/__init__.py`）。
  → 已全部 `brctl download` 拉回，现在 FLASH 内 dataless = 0，`git status` 干净、`git fsck` 只剩悬空 blob（正常）。
- `dev/wechat-monitor/` 还有 1430 个抽干（含 `.venv/bin/*` 二进制），`dev/` 合计 1595 个。

### 给的方案（待用户选）
1. 关「同步此 Mac 上的桌面与文档文件夹」——治本；关之前先全量 `brctl download`，否则可能丢云端副本（逻辑 2.1GB，本地剩 19GB 够）。
2. 关「优化 Mac 存储」——保留同步但不驱逐。
3. **推荐**：开发目录搬出 Desktop 到 `~/dev` 或独立 APFS 卷。搬法必须先物化再 rsync，**不能直接 mv**（同卷 mv 会把 dataless 占位符搬走，离开 iCloud 域后可能永远读不回来）。
4. iCloud 没有「排除子目录」官方机制，`.nosync` 那套对它无效。

### 教训
- macOS 上「文件在不在云端」看 `find -flags +dataless`，不是看 `.icloud` 占位文件（新 FileProvider 架构下 .icloud 文件已经不出现）。
- `git status` 干净 ≠ 文件内容可用：git 先比 stat，dataless 文件可能被判定 clean 而实际读不了。
