# 载具图片与名称规范方案（2026-10-17 23:14）

> 目标：修掉剩余错图/缺图，并把「只差空格/引号/连字符」的同名载具合并成同一型号。
> 本文只是方案，未改代码。

## 1. 名称规范化（对应问题 7）

### 1.1 现状

- 数据里共 **262 个名称字符串**
- 做「NFKC + 去空格 + 统一引号 + 去连字符/括号」后，实际只有 **203 个型号**
- 有 **58 组**重复，涉及 **117 个名称**
- 现在页面按原始字符串聚合，所以阵营内卡片数虚高：**378 → 实际应为 319 张**

典型重复组：

| 保留名（示例） | 被合并的异写 |
|---|---|
| M939 运兵卡车 | M939运兵卡车 |
| T-90A 主战坦克 | T-90A主战坦克 |
| T-72A | T72A |
| M-ATV M2 | MATV M2 |
| M-ATV CROWS M2 | MATV CROWS M2 |
| 米-8 河马 | 米-8河马 |
| KrAZ-6322 BM-21 “冰雹” | 同名的 `"冰雹"` / `“冰雹”` 三种引号写法 |
| MTLB 运输车 | MTLB运输车 |
| “山猫”全地形车运输型 QJZ89 | `"山猫" 全地形车运输型 QJZ89` |
| OH-6A “泥鳅” 轻型突击型 | `OH-6A "泥鳅" 轻型突击型` |

### 1.2 规范规则

新增 `vehicle-name.js`：

```js
canonicalKey(name):
  NFKC 归一
  去所有空白（半角/全角）
  去引号 “ ” " ' ‘ ’
  去连字符 - – —
  去括号 ( ) （ ）
  转大写
```

- **只做上述归一，不删型号字母/数字**，避免把 M113A3 和 M113A3 M2 误合并
- 原始 262 个名称全部保留为 alias，不丢数据
- 每个 canonical 选一个「标准展示名」（优先无多余空格、引号统一的写法）；58 组用人工确认表
- 阵营内按 canonicalKey 合并成一张卡；卡片保留该阵营所有编制的 entries
- 搜索同时匹配标准名 + 所有 alias
- 详情浮层可显示「别名：M939运兵卡车」作为提示

### 1.3 验收

- 数据仍保留 262 个原始名称
- 页面型号数从 262 → **203**
- 阵营卡片数从 378 → **319**
- 58 组合并逐组人工确认，确认表随代码提交
- 搜索任一异写都能命中同一张卡

## 3. 图片映射机制改造

当前 `vehicle-images.js` 是「名称正则 → 图片」，容易把同族/邻近型号套错。改为：

```js
// 以 canonicalKey 为主键，阵营可覆盖
VEHICLE_IMAGE_MAP = {
  'M939 运兵卡车': { image: '...', status: 'exact' },
  'CSK131 HJ8': { image: 'pla_csk131.png', status: 'same-chassis' },
  'T-90A 主战坦克': { image: '', status: 'missing' },
  'WPMC|M113A3 机动支援载具': { image: '...', status: 'exact' },
}
```

- 只有人工确认过的映射才写 `exact`
- 同底盘共用图写 `same-chassis`，浮层显示「同底盘变体」
- `missing` 一律返回空字符串 → 页面显示类别图标
- 不再用宽泛正则直接套图
