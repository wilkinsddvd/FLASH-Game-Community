```js

}
```

- Invasion 解析方式（数据已核验，44 层 / 22 图）：
  - `capturePoints.clusters.links` 本身就是「进攻方主基地 → 5 个进攻点 → 防守方主基地」的多条链
  - `capturePoints.clusters.pointsOrder` 会重复出现进攻方主基地，按它切分即可得到 A/B/C/D/E 各条进攻 lane
  - 每层 1–5 条 lane（20 层多 lane，24 层单 lane）；每条 lane 固定 5 个进攻点
  - 转成与 RAAS 相同的 `lanes / laneLinks / nodes` 结构，**直接复用 `buildRoutes` + `solveRoutes`**
  - `bidirectional: false`：Invasion 进攻方出生点固定为 team1 主基地，不需要像 RAAS 那样选边
- 图层页动态 `import()` 对应模式文件；地图列表只读 meta
- `raas-data.js` 保留 re-export 过渡

**页面**

- 模式卡只有 2 个：
  - **RAAS**：随机 lane，选出生点后逐步推测
  - **Invasion**：进攻方路线推测，进攻方出生点自动选中
- 地图列表只显示该模式有图层的地图
- Invasion 图层页复用 RAAS 的地图、确认面板、路线状态
- Invasion 交互：
  - 进攻方主基地自动作为第 0 点（不需要选边）
  - 地图上只展示进攻候选点，不展示防守方点位
  - 每确认一个实际看到的点，路线数收窄，显示「X / Y 条进攻路线仍然成立」
  - 单 lane 图层不直接剧透整条路线，仍按「确认—收窄」的方式展示；顶部提示「本图层仅 1 条候选路线」

### R6 · 火控计算器（4 天，含自动高程 / 网格坐标 / 等高线）

**路由 / 导航**

- `/squad/fire-control`，导航「火控计算器」

**首批武器**

| 武器 | 初速 | 单位 | 射界 |
|---|---|---|---|
| 标准迫击炮 | 110 | 密位 | 800–1579 |
| 技术车迫击炮 | 110 | 度 | -45–135 |
| M1064 M121 | 142 | 度 | -45–85.3 |
| Hell Cannon | 95 | 度 | 10–85 |
| UB-32 | 表 | 度 | -25–35 |
| BM-21 | 200 | 度 | -45–135 |

**计算**

- `d = hypot(dx, dy) / 100`
- `h = z_target - (z_src + heightOffset)`
- `g = 9.78 × gravityScale`
- `inner = v⁴ - g(g d² + 2 h v²)`
- `θ_low/high = atan((v² ∓/± √inner) / (g d))`
- `TOF = (v sinθ + √(v² sin²θ - 2gh)) / g`
- `mil = deg × 6400 / 360`
- 校验射界、最小射距、飞行时间

**基准（标准迫击炮，h=0）**

| 距离 | 密位 | 飞行时间 |
|---:|---:|---:|
| 300 m | 1475 | 22.3 s |
| 600 m | 1342 | 21.8 s |
| 900 m | 1185 | 20.7 s |
| 1200 m | 925 | 17.7 s |

**交互（极简：点两下 / 输两个坐标就出结果）**

- 选地图 → 选武器（默认标准迫击炮）→ 点炮位 → 点目标 → 出结果
- 炮位和目标都支持两种输入方式，二选一即可：
  - **地图点击**：点一下直接落点，网格坐标自动回填
  - **输入坐标**：手输**游戏网格坐标**（如 `D4`、`D4-6`、`D4-6-3`），回车即算
- 炮位可「锁定」：锁定后连续点目标，只需一次点击即可看新结果，适合边打边校射
- 输出：距离、方位角、仰角（主分支；有备选分支时一并显示）、飞行时间、最大射程、超程/近界提示
- 单位切换：**密位 / 度**（默认按武器：迫击炮用密位，车载武器用度）
- 高度差：**默认自动读取高程**（炮位/目标各取一次），显示两侧海拔与高差；可切换为「手动高差」覆盖
- 不做多目标表；保留交换炮位/目标、清空、复制结果

**游戏网格坐标**

- 口径（与游戏内一致）：
  - 大格：**300m × 300m**，从地图左上角（西北）起算；列 A/B/C… 向右，行 1/2/3… 向下
  - 一级 keypad：大格内 3×3，按小键盘布局（7/8/9 在上，1/2/3 在下）
  - 二级 sub-keypad：keypad 内再 3×3，同上
- 支持三种精度：`D4`（300m 格中心）、`D4-6`（约 100m 格中心）、`D4-6-3`（约 33m 格中心）
- 地图点击时，自动反算出 `列+行-keypad-sub` 填入输入框；鼠标移动时在角落显示当前网格
- 实现：`utils/squad-grid.js`
  - `gridToWorld(layer, "D4-6-3")`
  - `worldToGrid(layer, x, y)`
  - 基础：`minX/minY` 取自图层 `corners`，大格 300m，keypad 1-9 按 numpad 布局
- 网格坐标只负责定位；高程、弹道仍用反算后的世界坐标计算

**等高线图**

- 每张地图生成一张等高线图，放在火控地图**下方**；同时提供「在主图叠加」开关
- 数据源与自动高程同一套 500×500 高程，保证等高线与落点计算一致
- 生成脚本 `scripts/build-contours.py`：
  - marching squares 提取等高线
  - 等高距自适应：地形起伏 <200m 用 10m，200–500m 用 20m，>500m 用 50m；每 5 条加粗并标注高程
  - Douglas-Peucker 简化折线，输出 SVG（viewBox 与底图一致，0–1000）
  - 产物：`public/squad-assets/contours/<slug>.svg` + `data/squad/contours-meta.js`（等高距、海拔范围）
- 页面：
  - 下方「等高线图 · <地图名>」卡片：底图 + 半透明等高线 + 高程标注 + 图例
  - 主图叠加开关默认关闭，打开后同一 SVG 以绝对定位覆盖在底图上
  - 按地图懒加载 SVG，浏览器缓存

**自动高程（保证落点准确）**

- 数据：复用 `squadcalc.app/api/img/maps/<slug>/heightmap.json`（500×500，米），本地预处理后自托管
- 预处理脚本 `scripts/build-heightmaps.py`：
  - 抓取 23 张图的高程
  - 量化到 0.1m（int16），输出 `.bin`（500×500×2B ≈ 500KB/图）+ `heightmaps-meta.js`
  - 总量约 11.5MB，**按地图懒加载**，进入火控页只拉当前地图的一张
- 采样：双线性插值；行 0 = 北边 = `ymin`，与现有 `projectPoint` 的坐标方向一致
- 计算：`z_src = sampleHeight(src)`、`z_target = sampleHeight(target)`，再算 `h = z_target - (z_src + heightOffset)`
- 降级：高程文件缺失/加载失败 → 自动回退到 `h = 0`，并明确提示「未计地形，可手动输入高差」
- 精度：500×500 全分辨率，单格约 8m；丘陵图（Skorpo/Mestia）比 256 降采样显著更准（256 降采样在 Skorpo 最大误差可达数百米，不做）
