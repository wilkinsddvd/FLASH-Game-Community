## 2. 需求一：载具信息图片替换

### 2.1 步骤

1. 新增 `frontend/scripts/audit-vehicle-images.mjs`：以 `squad/public` 覆盖数据为准，输出 `docs/vehicle-image-audit.csv`
   （阵营 / 编制 / 型号 / 类型 / 当前图 / 状态 / 建议动作 / 建议来源），并对每张图校验文件存在 + 宽高比。
2. 按清单逐条找正确图（顺序见 2.3），下载原图 → `cwebp -q 82 -resize 900 0` → 存入 `public/squad-assets/vehicles/v2/`。
3. 更新 `vehicle-images.js` 映射（`VEHICLE_IMAGE_MAP` / `CANON_IMAGE_MAP`），命名统一 `<model>_infocard.webp`。
4. 复跑审计脚本：目标 `missing = 0`、错车用例清零、same-chassis 收敛（只保留真同底盘）。
5. 页面对照：载具信息页卡片 + 详情弹窗 + 编制详情浮窗（三处同源，自动一致）。
6. 兜底如果某车确实拿不到真图：保留同底盘图并在卡片角标「同底盘变体」，**不假装精确**。

### 2.2 优先级（先修"看着就不对"的）

P0：BMP-1TS、BMC-185（2）、山猫（4）、轻型改装皮卡 AGS-17、卡玛兹5320（确认后）
P1：护卫载具 M134、轻型 FSV、OH-6 侦察型
P2：橡皮艇 12 型（同艇体，统一加"武器站变体"标注）

### 2.3 BMP-1TS 取图路径（按你指定的顺序）

1. **联网搜索**（`web_search`）→ 官方 `joinsquad.com` 10.0 Trident Strike / AFU 相关页面渲染图（可直连取图）
2. **Squad Wiki**（`squad.wiki.gg`，API 可达；fandom 不可达）→ 文件检索 `BMP-1`、`AFU`；若只有 AFU 阵营首页图，接受其载具段图

4. 全都不行 → 兜底：沿用 `bmp_1_infosheet` 并角标「同底盘变体，BMP-1TS 炮塔/导弹不同」，同时在审计 CSV 记 `missing-source`，等你补图

每张替换图都会存来源 URL 到 `docs/vehicle-image-sources.md`（便于日后复核/换图）。

## 3. 需求二：编制浮窗

- 尺寸：宽 380–420px（<768px → 300px 或底部抽屉）；图片 `object-fit: contain`、`max-height: min(46vh, 320px)`（**不裁切**）
- 定位：按 `视口 - 浮窗 - 8px` 夹取，靠右/靠下自动翻转到光标左/上
- 内容：型号 / 类型 / 数量 / 票数 / 重生 / 初始延迟 / 备注 + 「查看完整资料 →」
- 交互：点击行 → `VehicleDetail` 弹窗（完整情报卡）；触屏单击直接开弹窗
- 与 §2 同源：浮窗图片走同一映射，图修完浮窗自动对

验收：1920/1366/390 三档 CDP 断言浮窗 rect 完全在视口内；图片宽高比误差 <2%；点开能看完整图。

## 4. 需求三：英文版（界面文案）+ CMS 文章双语

### 4-A 界面 i18n（不含编制/载具数据词典）

- 依赖 `vue-i18n@11`（npm 可达），`locales/zh-CN` / `locales/en-US` 按页面分模块 `import()` 懒加载
- Pinia `useLocaleStore` + `localStorage.flash_lang`；顶栏「中 / EN」胶囊一键切换，不刷新、不改路由、同步 `<html lang>`
- **只翻界面文案**：导航、按钮、表头、空态、提示、图例、页面标题、表单校验、错误信息（约 1200 条 key）
- **不翻**：阵营名、编制名、载具名、类型、部署物、战术、指挥官技能（按你的要求保持中文）
- 因此要处理"中文句子里嵌数据"的写法 → 统一改成插槽：`t('roster.vehiclesCount', { n })`
- 英文界面会是"英文界面 + 中文专有名"的混排，属预期效果
- 后台 `/admin/*` 保持中文

### 4-B CMS 文章双语（后端改动）

| 层 | 改动 |
|:-|:-|
| 模型 `model/article.py` | 加 `title_en` / `summary_en` / `content_en`（Nullable, String/Text） |
| 建表升级 | 沿用现有 `_REQUIRED_COLUMNS` 幂等补列（`db/db.py`），无需 alembic、不重建库 |
| Schema `schemas/cms.py` | `ArticleCreate/Update/Detail/ListItem` 增 `*_en` 字段 |
| API `api/cms.py` | 列表/详情支持 `?lang=zh|en`；`en` 时按"有英文用英文，缺则回退中文"返回，并带 `has_en` 标记 |
| 后台 `ArticleFormPage.vue` | 「中文 / English」两个 Tab；英文留空 = 回退中文，表单提示"未填写将显示中文" |
| 前端 `HomePage` / `ArticlePage` | 跟随语言取文章；英文缺失时标题旁加 `zh` 小标 |
| 范围外（后续可加同套字段） | Banner、系统通知、视频标题、答题库、留言板 |

验收：切英文后文章标题/摘要/正文显示英文；未填英文的文章仍可读并带 `zh` 标记；后台保存不丢中文字段；老数据不报错。

## 5. 需求四：其他页面沿用首页布局（1920 主力）

### 5.1 1920 下的实际宽度测算（避免"设了宽却没用上"）

```
视口 1920 → 容器 = 1920 - 24*2 = 1872
左右 rail 各 220 + 2 个 18px gap = 476
→ 主内容 ≈ 1396px（现有首页是 1560，需要按 1920 重新定标）
1440 → 容器 1392 - (180*2 + 36) = 996
1240 以下 → 单列，rail 折叠成顶部横滑条（沿用现有规则）
```

- 结论：`main-content` 不再写死 1200/1560，改为**由壳层计算**：`rail 220 / 内容 1fr`，内容不再单独限宽
- 各页删掉自己的 `max-width`（SquadPage 1200、SquadPoints 1200、SquadVehicles 1280/1360、FireControl 1400、RAAS 1400）

### 5.2 每页的多栏方案

| 页面 | 1920 下布局 |
|:-|:-|
| `/squad` | 左筛选栏 260（阵营/类型 sticky）+ 右阵营卡 3 列 |
| `/squad/:faction/:roster` | 左锚点目录 200 sticky + 中内容 + 右「载具速览」300 |
| `/squad/vehicles` | 左筛选 260 + 载具网格 4–5 列 |
| `/squad/points`、`/squad/points/:mode/:layer` | 地图区 + 右图例/面板 320（**保持地图零常驻遮挡**） |
| `/squad/fire-control` | 地图 1fr + 诸元栏 360 |
| `/cert`、`/guide` | 卡片 4 列 |
| `/article`、`/about` | 正文 820 居中（阅读优先），两侧留 rail |
| `/admin/*`、`/login`、`/register`、RAAS「铺满」档 | 白名单：满宽、无 rail |

验收：1920/1440/1366/1024/768/390 六档无横向滚动、无遮挡、无 CLS 跳变；RAAS 三档顶栏几何断言仍通过。

## 7. 需求六：火控地图可放大

- 视口 + stage 变换：滚轮以光标为锚缩放（1–8×）、`＋ / − / ⤾`、双指捏合、拖拽平移、双击复位
- 点击 vs 拖拽：位移 >6px 判拖拽不落点；落点反变换求 `u/v`，`worldToGrid` 回填逻辑不变
- 网格 / 等高线 / 炮位-目标连线 / 标记跟随变换；网格文字走「叠加层不缩放」保证清晰
- 触屏 `touch-action: none`（盘面内不误滚页面）

验收：缩放后标记 `u/v` 误差 <0.2%；拖拽不误落点；鼠标/触屏/按钮三路径可用。
