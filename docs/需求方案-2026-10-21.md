## 2. 需求 ①：网页端移动适配优化

### 2.1 目标

- 360–430px 主流手机、768px 平板、桌面三档都“能顺手用”，而不是“能看不炸”。
- 关键路径（首页 → 点位 → 火控 → 认证 → 关于）全部单手可完成。
- 移动端首屏 JS gzip ≤ 300KB，4G 中端机 LCP ≤ 2.5s。

### 2.2 改动方案

**A. 设计口径（全局）**

| 项 | 口径 |
|---|---|
| 断点 | xs < 480；sm 480–767；md 768–1023；lg ≥ 1024（沿用现有 480/640/768，补 1024） |
| 触控目标 | 主要可点元素 ≥ 44×44；次要 chip ≥ 40×40；纯文字链接可例外但要加 8px 内边距 |
| 输入框 | 移动端 `font-size: 16px`（防 iOS 自动放大）；坐标输入 `inputmode="text"`、`enterkeyhint="done"` |
| 安全区 | header/footer/底部抽屉统一 `env(safe-area-inset-*)`；地图高度用 `100dvh` 不用 `100vh` |
| hover | 所有 hover 才出现的信息，在 `@media (hover: none)` 下改为常显或点击展开 |
| 动效 | 尊重 `prefers-reduced-motion`；移动端关闭非必要过渡 |

**B. 逐页改动**

| 页面 | 改动 |

### 3.3 数据与算法：单一来源 + 一致性测试

现状是网页版 `raas.js` / `fire-control.js` / `squad-grid.js` 都是**纯 ESM 函数**（无 DOM），这是好消息。

做法：

1. 把三个文件整理为“共享核心”（仅做导出收敛，不改算法）。
2. 新增 `scripts/sync-mp-core.mjs`：
   - 从 `frontend/src/utils/{raas,fire-control,squad-grid}.js` 生成小程序可用的 `utils/*-core.js`（去掉 ESM export 语法或统一转 CommonJS/TS 兼容写法）。
   - 生成文件头写 `// AUTO-GENERATED from <path> @ <sha>，勿手改`。
3. 新增 `scripts/test-mp-parity.mjs`：
   - 对 **全部 83 个图层**（39 RAAS + 44 Invasion）比较 `buildRoutes` 的路线集合、点序、深度；
   - 对火控：20 张地图 × 全部武器 × 每图 50 组随机坐标，比较距离/仰角/方位/飞行时间（误差 < 1e-9）。
   - 任何差异 → 非零退出，禁止发版。
4. 数据生成 `scripts/build-mp-points-data.mjs`：从网页数据产出压缩 JSON（预计 RAAS ~250KB、Invasion ~110KB），放 `packagePoints/data/`；不进主包。

### 3.4 地图交互（小程序重写部分）

用 `<canvas type="2d">` 一块画布同时画底图与点位，避免多层 `<image>` 叠加的性能问题。

| 交互 | 行为 |
|---|---|
| 单指拖拽 | 平移；边界回弹 |
| 双指 | 缩放（1×–4×），以两指中心为锚点 |

## 4. 需求 ③：第三方登录

### 4.1 渠道矩阵

| 渠道 | 协议/接口 | 需要什么 | 备注 |
|---|---|---|---|
| 微信（Web） | 开放平台网站应用 `qrconnect`，`snsapi_login` | 微信开放平台账号（**企业主体**）+ 网站应用审核（300 元/年）+ 授权回调域名 | 个人主体基本申请不下来，需提前确认 |
| 微信（小程序） | `wx.login` → `jscode2session` | 现有小程序 AppID/Secret | 无额外费用，最快落地 |
| QQ（Web） | QQ互联 OAuth2.0（`graph.qq.com`） | QQ互联开发者资质 + 已备案回调域名 | 需 `get_user_info` 拿昵称头像 |
| Steam（Web） | OpenID 2.0（`steamcommunity.com/openid/login`） | 无需注册应用；可选 Web API Key | 用 SteamID64 作为 openid |

> 本地开发回调必须是公网 HTTPS：用 cloudflared/ngrok 临时隧道，或直接在 staging 联调。不要在本地硬编码 `127.0.0.1` 回调。

### 4.2 数据模型（小迁移）

```sql
-- 1) 允许第三方账号无密码
ALTER TABLE users MODIFY password_hash VARCHAR(128) NULL;

-- 2) user_oauth 复用，provider 取值扩展
--    wechat_web / wechat_mp / qq / steam
--    unique(provider, openid) 已存在
-- 3) 可选：记录最近登录时间（便于安全审计）
ALTER TABLE user_oauth ADD COLUMN last_login_at DATETIME NULL;
```

- 纯第三方用户：`password_hash=NULL`，用户名自动生成（`wx_xxxx` / `qq_xxxx` / `steam_xxxx`），`uid` 走现有发号器。
- 登录接口遇到 `password_hash IS NULL` 直接返回“该账号仅支持第三方登录”，避免空指针/绕过。
- 迁移写进 `db/db.py::_REQUIRED_COLUMNS`（幂等补列），不引入 Alembic。

### 4.3 统一 OAuth 模块

新增 `api/oauth.py`（`/api/auth/oauth/*`），`api/wechat.py` 保留兼容并转发。

```
GET  /api/auth/oauth/providers                 # 返回已配置渠道（前端决定显示哪些按钮）
GET  /api/auth/oauth/{provider}/authorize      # 生成 state（Redis 10min）→ { url }
GET  /api/auth/oauth/{provider}/callback       # 校验 state → 换 openid → 302 前端 /oauth/callback?ticket=xxx
POST /api/auth/oauth/exchange                  # { ticket } → { access_token, refresh_token, user }
GET  /api/auth/oauth/bindings                  # 当前用户绑定列表（不含 openid）
POST /api/auth/oauth/{provider}/bind           # 已登录时绑定
POST /api/auth/oauth/{provider}/unbind         # 解绑（若为唯一登录方式则拒绝）
```

小程序专用：

```
POST /api/auth/wx/login   { code }                       # code2session → 登录/自动建号
POST /api/auth/wx/bind    { bind_ticket, mode, username?, password?, captcha? }
```

**流程规则（Web）**

1. 匿名点“微信登录” → authorize → 回调。
2. `(provider, openid)` 已存在 → 直接登录（检查封禁）。
3. 不存在，但当前有登录态 → 绑定到当前账号。
4. 不存在且未登录 → 自动建号（同样检查 unionid：
   - `wechat_web` 与 `wechat_mp` 的 openid 不同，但 unionid 相同 → 视为同一人，自动合并到同一账号）。
5. 前端拿到 `ticket` 后 `POST /exchange` 换 JWT。**JWT 绝不出现在 URL/Referer/日志里。**

**流程规则（小程序）**

1. `wx.login()` 拿 code → `/api/auth/wx/login`。
2. 后端 `jscode2session` 拿 openid/unionid；`session_key` **不返回前端、不落库**（除非后续要解密手机号）。
3. 已存在 → JWT；不存在 → 自动建号（`provider=wechat_mp`）。
4. 想把微信身份绑到网页老账号：返回 `need_bind + bind_ticket`，前端引导输入用户名/密码/验证码，`/wx/bind` 完成绑定。
5. 可选：`wx.getUserProfile` 已废弃，昵称头像走现有审核队列（`pending_nickname/pending_avatar`），不要直接覆盖展示字段。

### 4.4 安全清单

- `state` 一次性、Redis TTL 10 分钟；`ticket` 一次性、TTL 60 秒。
- 所有 OAuth 回调校验 `provider` 白名单；Steam 必须回源 `check_authentication` 验签，不能只信 query。
- 登录/绑定接口限流（IP + openid 维度），失败日志脱敏。
- 不对外返回 openid/unionid；管理后台也不展示明文。
- 解绑保护：账号没有密码且只剩一个绑定 → 拒绝解绑。
- 封禁用户（`banned_until`）在 OAuth 登录链路同样拦截。
- 审计：登录、绑定、解绑写 `audit` 日志（已有审计模块）。

### 4.5 前端 / 小程序改动

- `LoginPage.vue`：三个品牌按钮（微信/QQ/Steam）+ “账号密码登录”分隔；渠道未配置时隐藏（读 `/providers`）。
- 新增 `pages/OauthCallback.vue`：读 `ticket` → exchange → 存 token → 回跳原页面。
- `Settings/ProfileSettings`：绑定管理（已绑定/去绑定/解绑）。
- 小程序：`关于` 页加账号区（头像/昵称/登录/退出）；提问、反馈提交等需要身份的操作在未登录时引导登录；`app.ts` 启动时不再静默登录（改为按需，降低审核与隐私风险）。

### 5.6 L5 压力测试

新增 `FLASH_END_PRO/tests/load/locustfile_mp.py`：

| 任务 | 权重 |
|---|---:|
| 首页聚合（banner/videos/articles） | 30% |
| 编制列表/详情 | 25% |
| 认证题库/提交 | 10% |
| 点位图层 meta/数据 | 20% |
| 静态资源（地图 webp / 高程 bin / 等高线 png） | 15% |

- 场景：50 / 100 / 200 并发，10 分钟；再跑 30 分钟长稳。
- 阈值（staging）：错误率 < 0.5%；读接口 p95 < 300ms、p99 < 800ms；静态 p95 < 500ms。

### 5.7 L6 运行时

- `wx.getPerformance()` 打点：冷启动、页面切换、首图渲染、图层数据加载。

- 报告：`tests/reports/mp-<date>.md`（功能矩阵 + 压测表 + 包体积 + 性能打点）。

## 8. 风险与需要你确认的事

### 风险

1. **资质是硬门槛**：微信网页登录要企业主体开放平台（300 元/年）；QQ 互联要备案域名。没有资质时，代码可以先合，但只能显示“暂未开放”。
2. **小程序域名**：地图 66MB、高程 11MB 必须放 HTTPS + downloadFile 合法域名；备案没下来前只能开发者工具/真机调试模式跑。
3. **canvas 性能**：低端安卓上 100+ 点位 + 标签可能掉帧，需要“密图规则 + 视口裁剪 + 标签碰撞”，必要时降级为只显示圆点。
4. **两套代码漂移**：网页与小程序求解器必须靠 parity 测试锁死，不能靠人肉同步。
5. **小程序无版本管理**：改前必须备份 / 初始化 git，否则回滚困难。

### 需要你拍板（回复编号即可）

1. **留言板**：小程序只隐藏入口（推荐），还是彻底删页面？后端接口是否保留？
2. **第三方登录资质**：微信开放平台/QQ 互联是否已有？没有的话我先按“可配置、未配置则隐藏”的方式实现，等你资质下来再联调？
3. **Steam**：是否必须首版就有？它不依赖审核，可以最先做。
4. **后台管理页**：移动端是否接受“仅提示、仍以桌面为主”？
5. **火控等高线**：小程序 v1 先不做（推荐），还是必须与网页同时上？
6. **小程序代码**：是否同意 `git init` 纳入版本管理（独立仓库，不并进 FLASH）？
