## 1. 需求一：编制图 / BMP-1TS 图片错误

### 1.1 现状核查（已跑数据）

- 载具记录 **891 条**、去重型号 **267 个**；`public/squad-assets/vehicles/*.png` 小图标仅 **60 张**，`vehicles/v2/*.webp` 情报卡 **168 张**。
- 页面取图优先级：`vehicleImageFor(name)`（vehicle-images.js，**255/267 命中**）→ 回退 `icon_url`。
- **BMP-1TS 两处引用（AFU 第28机械化旅 2 台 / 第11集团军 1 台）**：
  - `icon_url: /squad-assets/vehicles/mea_bmp1.png` ← MEA 的 BMP-1 图，**这是错图来源**
  - 详情卡映射：`v2/bmp_1_infosheet.webp` ← 苏联原版 BMP-1，**不是乌克兰 BMP-1TS**；仓库内无 BMP-1TS 独立素材（已全盘搜 `*1ts*` / `*bmp*`）
- **编制（roster）类型图**由 `NATO_ICON(type_key)` 现生成，发现 type_key 与名称语义不符：
  - `mechanized` 第108近卫空中突击团（VDV，应为 airassault）
  - `combined` 第7近卫山地空中突击师（应为 airassault）
  - `motorized` 加拿大第 12 装甲团（应为 armored）
  - ADF 两个编制同名「澳大利亚皇家军团第一营」（mechanized / motorized）→ 列表与搜索混淆
- **135 条 icon_url 属近似复用**（系统性错配），而 v2 里其实有正确图：
  `T-64BM2→rus_t72.png`、`BTR-4→rus_bmp2.png`、`Kozak-2M1→rus_tigr.png`、`ACV-15 / PARS III / Cobra II / M60T→mea_bmp1.png`、`MTLB→rus_btr80.png`、`KrAZ-6322→mea_ural4320.png` …

### 1.2 方案

1. 新增 `scripts/audit-squad-images.mjs`：遍历 `factions.js` + `vehicle-images.js`，输出 `docs/squad-image-audit.csv`
   （阵营 / 编制 / 型号 / 类型 / 当前图 / 建议图 / 文件是否存在 / 状态 exact·same-chassis·missing），同时校验 webp 尺寸比例。
2. 依审计结果批量修正 `icon_url` 与 `vehicle-images.js` 映射（用已有 v2 素材，不新增外部资源）。
3. BMP-1TS 单独处理，三选一（**待你拍板**）：
   - a. 你提供图片或可用链接（最准确，我放入 `vehicles/v2/bmp_1ts_infocard.webp` 并映射）
   - b. 先用同底盘素材（`bmp_1_infosheet` 或 `bmp_1_zu_23_infocard`），在 UI 上标「同底盘变体，炮塔不同」
   - c. 生成带型号字样的示意卡（不推荐，视觉会露馅）
4. 修正上述 3–4 处 type_key，ADF 重名改为「澳大利亚皇家军团第 1 营（机械化）/（摩托化）」。
5. 兜底：小图标（60 张 PNG）在详情卡覆盖后已无必要，可把 `icon_url` 降级为「无图时的类别图标」，从根上避免再次出现错配小图。

### 1.3 验收

- 审计 CSV：`missing = 0`；BMP-1TS 行有独立图且不等于 BMP-1。
- 80 个编制的 type_key 与名称语义一致；重名 0。
- 抽检 20 个编制页：小图与大图型号一致（脚本比对文件名 token）。

## 2. 需求二：编制浮窗显示过小

### 2.1 现状

`SquadRosterPage.vue`：`.custom-tip { min-width: 220px; max-width: 300px }`，`.tip-img { height: 70px; object-fit: cover }`（裁切），定位 `left/top = clientX/Y + 14`，**无边界夹取** → 右侧/底部溢出被裁，且图片被压扁裁切看不全。

### 2.2 方案

- 尺寸：宽度 380–420px（<768px 时 300px 或改为底部抽屉），图片 `object-fit: contain`、`max-height: min(46vh, 320px)`、白/深底自适应。
- 定位：按 `视口 - 浮窗尺寸 - 8px` 夹取；靠右/靠下时自动翻转到光标左/上。
- 内容：型号 / 类型 / 数量 / 票数 / 重生时间 / 初始延迟 / 备注 + 「查看完整资料 →」。
- 交互：点击行 → 复用 `VehicleDetail.vue` 弹窗显示完整情报卡（大图 + 尺寸/武器数据）；触屏（无 hover）单击直接开弹窗。
- 细节：图片预加载相邻 2 行；浮窗出现/消失保留 0.15s 淡入。

### 2.3 验收

- CDP 断言：1920 / 1366 / 390 三档，浮窗 `rect` 完全落在视口内（含贴边 8px 安全区）。
- 图片 `naturalWidth/naturalHeight` 比例与展示比例误差 <2%（不裁切）。
- 点击行能打开完整资料弹窗；移动端不出现"点了没反应"。

## 3. 需求三：英文版一键切换

### 3.1 技术选型

- `vue-i18n@11`（npm 可达，已验证 11.4.16）。locales 按页面拆分、动态 `import()` → 首屏只加载当前语言。
- 语言状态存 Pinia `useLocaleStore` + `localStorage.flash_lang`（默认 `zh-CN`），切换时同步 `<html lang>`，**不刷新、不改路由**。
- 顶栏放「中 / EN」胶囊切换（与主题按钮并列），移动端收进导航抽屉。

### 3.2 范围（关键）

- **翻译**：全站界面文案（导航、按钮、表头、空态、提示、错误、图例）+ 静态数据（阵营名、编制名、编制类型、编制特性、部署物、指挥官技能、载具名/类型/备注）。
- **载具英译规则**：型号保留原文 + 类型词表（步兵战车→IFV、主战坦克→MBT、运兵卡→Transport Truck …），另加约 60 条人工覆盖（橡皮艇→RHIB、改装皮卡→Technical、"冰雹"→Grad …）。
- **不翻译**：`/admin/*` 后台（超管自用，保持中文）、CMS 内容（资讯/视频/答题/公告，英文模式显示原文并加 `zh` 角标）。
- 若后续要 CMS 双语：后端加 `title_en` / `content_en` 字段 + 后台编辑页，另立需求（不在本次）。

### 3.3 工程量拆分

| 子任务 | 内容 | 人日 |
|:-|:-|:-:|
| i18n 基建 | 依赖、store、切换按钮、按页懒加载、`<html lang>` | 0.5 |
| 界面文案抽取 | 约 1200 条 key（App/Home/Squad 系/火控/认证/攻略/关于/认证/登录注册/社区） | 1.5 |
| 数据词典 | 80 编制 + 267 型号 + 类型词表 + 人工覆盖 | 1.0–1.5 |
| 回归 | 漏译扫描 + 双语布局回归 | 0.5 |

### 3.4 验收

- 切换后 DOM 中文占比扫描（白名单：CMS 内容、专有名词）→ 0 漏译。
- 刷新保持语言；两语言都不出现横向溢出；构建产物中两个 locale 各自独立 chunk。
- 语言切换不影响火控已算出的诸元、点位已确认状态。

## 4. 需求四：其他页面沿用首页布局，左右两侧充分利用

### 4.1 现状

- `App.vue`：`.main-content { max-width: 1200px }`，仅 `meta.wide`（首页）= 1560。
- 首页自己有 `.home-shell` grid（180 + 1fr + 180）+ 左右 banner rail + <1240 折叠规则；**其他页面完全没这套**。
- 各页各自硬编码宽度：SquadPage 1200、SquadPoints 1200、SquadVehicles 1280 / 1360、FireControl 1400、RAAS Layer 1400、About 760、Article 820 → 1920 屏大量空白。

### 4.2 方案

1. **版式所有权上收**：把首页的 `home-shell`（左右 rail + 断点折叠）抽成全局壳层，`SideBanners` 在 App 层渲染（左右交替分栏逻辑照搬），页面只负责内容。
2. **默认宽屏**：`main-content` 默认 1560（`meta.narrow` 才收紧），各页移除自己的 `max-width`，改 `width:100%`。
3. **按页做真正的多栏**（这才是"充分利用"的实质）：
   - `/squad`：左阵营/类型筛选 sticky + 右侧阵营卡 3 列
   - `/squad/:faction/:roster`：左锚点目录 sticky + 中内容 + 右「载具速览」栏
   - `/squad/vehicles`：左筛选 260px + 右载具网格 4–5 列
   - `/squad/points`、`/squad/points/:mode/:layer`：地图区 + 右侧图例/面板并排（**必须保持"地图区零常驻遮挡"的既有约定**）
   - `/cert`、`/guide`：卡片 4 列；`/squad/fire-control`：地图 1fr + 诸元栏 360
4. **例外白名单**：`/admin/*`、`/login` `/register`、文章/关于正文（限 820 阅读宽，两侧留 rail）、RAAS「铺满」档（`meta.fullBleed`，不受 rail 限制）。
5. 断点：≥1440 三列(rail)、1240–1440 窄 rail、<1240 单列（沿用现有规则，不新增断点）。

### 4.3 验收

- 1920 / 1440 / 1366 / 1024 / 768 / 390 六档：`documentElement.scrollWidth <= innerWidth`（无横向滚动）、无 rail 压内容、无 CLS 跳变。
- 布局改造后 RAAS 三档（适配/大/铺满）顶栏几何一致性断言仍通过。

## 5. 需求五：首页入口大图标

- 首页顶部新增「功能入口」区（位于 Banner 之下、资讯之上）：**编制 / 点位 / 载具 / 火控 / 认证 / 攻略 / 视频 / 社区** 共 8 个。
- 每卡：大图标（内联 SVG，24→44px，跟随暗/亮主题描边）+ 中文名 + 英文副标（与 i18n 联动）+ 一句说明 + hover 抬升/描边发光。
- 响应式：≥1440 → 4×2；992–1440 → 3 列；768 → 2 列；<480 → 2 列紧凑（图标缩小）。
- 纯 SVG/CSS，不新增图片资源（无加载抖动、可换色、主题自适应）。
- 顶部导航保留不动；若你希望只留图标入口，可后续把导航收成「更多 ▾」。

验收：Tab 可达 + Enter 进入；每卡 `aria-label`；对比度 AA；8 个入口路由全部命中。

## 6. 需求六：火控计算器地图支持放大

`components/FireControlMap.vue` 目前无缩放（`aspect-ratio: 1/1` 固定），RAAS 地图（`RaasMap.vue`）已有成熟手势层可复用。

- 视口 + stage 变换：滚轮以光标为中心缩放（1×–8×）、`＋ / − / ⤾` 按钮、双指捏合、拖拽平移、双击放大（再双击复位）。
- **点击 vs 拖拽**：位移 >6px 判定拖拽，不落点；落点用 stage 反变换求 `u/v`，坐标/网格回填逻辑不变（仍走 `worldToGrid`）。
- 网格、等高线、炮位-目标连线、标记全部跟随 stage 变换；网格文字与标签用「叠加层不缩放」做法（原生清晰度，不随放大变糊）。
- 交互细节：盘面 `touch-action: none`（手机不误滚页面）、缩放百分比显示、esc 复位。

验收：缩放后 marker 的 `u/v` 换算误差 <0.2%；拖拽不误落点；鼠标/触屏/按钮三条路径都生效；三档视口可用。
