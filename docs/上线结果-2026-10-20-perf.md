## 2. 关键发现：边缘 nginx 把压缩吃掉了

- 容器内（`docker exec ... curl 127.0.0.1:3000`）**有** `Content-Encoding: gzip`；宿主机 `curl 127.0.0.1:3000` 也**有**。
- 但公网 `https://squadflash.cn/...` 拿到的仍是 `content-length: 500000`（未压缩）→ 宿主机 nginx（1.18，443 终止 TLS 后反代 3000）这一段丢了压缩。
- 处理：**在边缘补 gzip**（`/etc/nginx/nginx.conf` 的 gzip 段，原本只开了 `gzip on`，其余全被注释）：
  - `gzip_vary on` / `gzip_proxied any` / `gzip_comp_level 6` / `gzip_min_length 1024`
  - `gzip_types` 增加 `application/octet-stream`（高程 `.bin`）与 `image/svg+xml`（等高线）
- 备份：`/root/backups/nginx.conf.bak-20261020-050331`；`nginx -t` 通过后 `systemctl reload nginx`。

效果（公网实测）：

| 资源 | 传输字节 |
|---|---:|
| `/squad-assets/heightmaps/mutaha.bin` | 500,000 → **126,782**（−75%） |
| `/squad-assets/contours/mutaha.svg` | 64,775 → 压缩（原来完全没压） |
| `/assets/index-*.js` | 196,197 → gzip |

> 注意：**容器内 nginx 的 gzip 配置保留**（本地/其它环境仍然有效），只是这一层在生产链路里被边缘 nginx 覆盖。
