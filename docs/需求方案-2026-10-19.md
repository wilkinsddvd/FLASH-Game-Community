### 1.2 方案

**第一步：先做审计，再补图（避免继续“猜图”）**

新增 `scripts/audit-vehicle-images.mjs`：

- 遍历 80 个编制 → canonical 型号 → 实际图片
- 输出 `docs/vehicle-image-audit.csv`：`阵营, 载具, 类别, 图片, 状态(exact/same-chassis/missing), 同图其他型号, 文件是否存在`
- 输出 `docs/vehicle-image-contact-sheet.html`：按阵营拼图，每张图下方标注型号，方便你一次性肉眼确认

**第二步：映射表升级为“带状态的对象”**

`frontend/src/data/squad/vehicle-images.js` 从 `name -> url` 改为：

```js
'M1151 陶氏反坦克导弹': { image: '...', status: 'same-chassis', note: 'M1151 底盘 / TOW 武器站' },
'轻型 FSV':           { image: '',    status: 'missing' },
'T-90A 主战坦克':      { image: '...', status: 'exact' },
```

- 只有人工确认过的才写 `exact`
- 同底盘共用写 `same-chassis`，`VehicleDetail` 显示提示
- `missing` 一律返回空 → 页面显示 15 类图标
- 保留 `vehicleImageFor()` / `isGenericOnly()` 兼容旧调用

**第三步：联网抓图脚本**

新增 `scripts/fetch-wiki-vehicle-images.mjs`：

- 来源优先级：Squad Wiki（MediaWiki API，`squad.fandom.com`）→ squadmaps 资源库 → 人工提供截图
- 走代理 + 重试（Wiki 直连会 403/超时）；每次抓取记录 `page title / file url / license`
- 下载后统一转 `webp`（宽 480），落到 `public/squad-assets/vehicles/v2/`
- 抓不到就写 `missing`，**不允许拿近似型号顶替**

**第四步：人工确认闭环**

- 生成 contact sheet → 你确认 → 回填状态表
- 确认后的映射表随代码提交，审计 CSV 一并提交

### 1.3 验收

- 本章 1.1-B 表中的错图全部处理（换图 / 回退同底盘 / 回退类别图标）

## 7. 需求 7：“RAAS 点位” → “点位推测”，先选模式再选地图

> 2026-10-20 02:17 更新：范围收敛为 **只新增 Invasion**；AAS/Seed/Skirmish/TC/Insurgency/Destruction 暂不做。
> Invasion 只需做**进攻方**路线推测，点位规则与 RAAS 一致（数据里 `clusters.links` 天然是多条进攻链，可直接转成 lane 复用求解器）。施工口径见 `docs/施工计划-2026-10-20.md` 的 R5。

### 7.1 数据可行性（已核验原始库）

| 模式 | 可用图层 | 地图 | 点位结构 | 可做的展示 |
|---|---:|---:|---|---|
| RAAS | 39 | 23 | `lanes + laneLinks + nodes` | **随机 lane 预测**（现有求解器） |
| AAS | 44 | 23 | `pointsOrder`（固定旗序） | 固定路线，按顺序编号 |
| Invasion | 44 | 22 | `clusters.links`（固定链） | 进攻/防守固定点位链 |
| Skirmish | 33 | 23 | `pointsOrder`（固定） | 固定小图点位 |
| Seed | 14 | 12 | `pointsOrder`（固定） | 固定 3 点 |
| TC | 18 | 16 | `pointsOrder` + hex | 静态点位（二期） |
| Insurgency | 9 | 9 | `pointsOrder` + 目标点 | 静态点位（二期） |
| Destruction | 4 | 4 | `pointsOrder` + 阶段区域 | 静态点位（二期） |
| Fireteam | 7 | 7 | `pointsOrder` 名称无法完全对上 | **不纳入**（数据质量问题） |
| Training | 2 | 1 | 固定 | 不纳入 |

> 关键结论：**只有 RAAS 有随机性**。AAS/Invasion/Seed/Skirmish 是固定点位，页面不能继续叫“预测”，应展示“本图层固定旗序/点位链”，避免误导。

### 7.2 信息架构 / 路由

```
/squad/points                        模式选择（大卡片）
/squad/points/:mode                  该模式的地图列表
/squad/points/:mode/:layer           点位工具（地图 + 点位）
```

- 模式 key：`raas | aas | invasion | seed | skirmish`（二期 `tc | insurgency | destruction`）
- 旧链接兼容：
  - `/squad/raas` → `/squad/points`
  - `/squad/raas/:layer` → `/squad/points/raas/:layer`
- 顶部导航文案：`RAAS点位` → `点位推测`

### 7.3 页面

**模式选择页**：5 张大卡（图标 + 模式名 + 一句话说明 + 图层数 / 地图数）
- RAAS：随机 lane，需要逐步确认点位
- AAS / Invasion / Seed / Skirmish：固定点位，直接看布局

**地图列表页**：当前模式的地图卡片 + 搜索 + “隐藏社区层”；每张图列出 v1/v2/v3/CL 图层按钮
- 只显示该模式有图层的地图（例如 Seed 只有 12 张图）

**图层页**：
- RAAS：完全复用现有 `SquadRaasLayerPage` 的求解器 / 确认面板 / 路线状态
- 非 RAAS：隐藏“确认点位 / 路线状态”面板，改为展示：
  - 固定旗序列表（第 1 点、第 2 点…，含名称与半径）
  - 两个主基地（出生点）
  - 可选“高亮某一阵营出生点”
  - 顶部提示：“本模式为固定点位，无需推测”

### 7.4 数据脚本改造

把 `scripts/build-raas-data.py` 重构为 `scripts/build-points-data.py`：

- 支持 `--modes RAAS,AAS,Invasion,Seed,Skirmish`
- 统一图层结构：

```js
{
  mode, raw, name, map, ver, community, size, corners, teams,
  // RAAS 专用
  lanes, laneLinks, nodes,
  // 固定模式专用
  order: [{ id, n, x, y, r, main, team }],
  links: [[a, b]],          // Invasion
}
```

- 产出按模式拆分，避免首屏过大：
  - `data/squad/points-meta.js`：模式清单 + 每模式的地图/图层索引（小）
  - `data/squad/points/raas.js`（约 300KB）
  - `data/squad/points/aas.js`（约 340KB）
  - `data/squad/points/invasion.js`（约 340KB）
  - `data/squad/points/seed.js`（约 110KB）
  - `data/squad/points/skirmish.js`（约 250KB）
- 图层页 `import()` 动态加载对应模式文件；地图列表只读 meta

## 8. 需求 8：新增“火控计算器”

### 8.1 参考实现与数据（不重复造轮子）

- 弹道模型 / 武器参数：`aachtenberg/squadmaps-v2`（MIT），已核对其 `computeFiringSolution` 公式与 Squad 游戏内参数
- 武器预设：其 `WEAPONS` 表（原版 7 种 + mod 若干），可裁剪为原版 6 种
- 地图高程：`squadcalc.app/api/img/maps/<slug>/heightmap.json`（500×500，米）；单图约 2.4MB，全量约 58MB，需自托管 + 压缩
- 地图底图 / 坐标：直接复用现有 `raas-data.js` 的 `corners` 与 `projectPoint`

### 8.2 功能范围（P1）

- 选择武器 → 选择地图 → 地图上点“炮位”和“目标”（或手输坐标/距离）
- 输出：水平距离、方位角（密位/度）、仰角（主分支）、备选分支、飞行时间、最大射程、是否低于最小射距、是否超出射程
- 支持交换炮位/目标、清空、复制结果
- 高度差：P1 手输（默认 0）；P2 自动高程

**首批武器预设（原版）**

| 武器 | 类型 | 初速 | 角度单位 | 射界 | 备注 |
|---|---|---|---|---|---|
| 标准迫击炮（部署物） | 高抛 | 110 m/s | 密位 800–1579 | 45°–88.8° | 最常用 |
| 技术车迫击炮 | 高抛 | 110 m/s | 度 -45–135 | 含偏移修正 | |
| M1064 M121 120mm | 高抛 | 142 m/s | 度 -45–85.3 | 车体 | 两种弹（Impact / Near Surface） |

> mod 武器（TOS-1A、M777、HIMARS 等）二期按需加，不占首版工作量。

### 8.3 计算模型（与参考实现一致）

- 坐标：世界单位 cm → 米；`d = hypot(dx, dy)/100`
- 方位角：`atan2(dx, -dy)`，0°=北，顺时针；`v` 轴向下 = 南
- 高差：`h = z_target - (z_src + heightOffset)`
- 重力：`g = 9.78 * gravityScale`
- 判别式：`inner = v⁴ - g(g d² + 2 h v²)`；`inner < 0` → 超程
- 两解：
  - 低伸：`θ_low = atan((v² - √inner)/(g d))`
  - 高抛：`θ_high = atan((v² + √inner)/(g d))`
- 飞行时间：`t = (v sinθ + √(v² sin²θ - 2gh)) / g`
- 密位换算：`mil = deg × 6400/360`（Squad 6400 密位制）
- 有效性：解在武器射界内 + `d ≥ minDistance` + 飞行时间 ≤ 弹丸寿命
- 主分支：`angleType = high` 取高抛（迫击炮通常只有高抛解在 800–1579 mil 内）

**基准用例（标准迫击炮，v=110，g=9.78，h=0）**

| 距离 | 高抛角 | 密位 | 飞行时间 |
|---:|---:|---:|---:|
| 300 m | 82.98° | 1475 | 22.3 s |
| 600 m | 75.50° | 1342 | 21.8 s |
| 900 m | 66.66° | 1185 | 20.7 s |
| 1200 m | 52.04° | 925 | 17.7 s |

> 最大射程 `v²/g ≈ 1237 m`；低伸解在标准迫击炮上均低于 800 mil，因此界面只显示高抛解并提示“另一解不在射界内”。
