# 载具页面改版方案（2026-10-17）

> 目标：大图标、分阵营、不展示数量、悬停看大图与详细信息；补全原版载具武器/弹药数据；纠正错误载具图片。
> 本文只是方案，未改代码。

---

## 1. 现状盘点

- 页面：`frontend/src/pages/SquadVehiclesPage.vue`
  - 现有「按载具」表格 + 「按阵营」列表两种视图
  - 载具图标约 56px，列表里显示 `×数量`、阵营「共 X 台」、页头「共 X 台」
- 数据：`frontend/src/data/squad/factions.js` 的 80 份编制
  - 262 个载具名称口径
  - 字段只有：name / type / category / count / tickets / respawn_time / initial_delay / icon_url / note
  - **没有武器、弹药、乘员等字段**
- 图片：`frontend/public/squad-assets/vehicles` 共 59 个文件，262 个名称共用
  - 大量「一个图代整个车族」，且不少明显错配，例如：
    - `mea_ural4320.png` 被 24 个名称共用（KrAZ-6322、BMC-185、BM-21……）
    - `imf_technical.png` 被 23 个名称共用（萨菲尔、明斯克摩托、现代皮卡……）
    - `mea_bmp1.png` 被 14 个名称共用，其中包含 **M60T 主战坦克**、ACV-15、PARS III
    - `rus_t72.png` 同时用于 T-72B3 / T-90A / T-64BM2 / T-62 / T-72A
    - `rus_btr80.png` 同时用于 BTR-80 / BRDM-2 / MT-LB
    - `us_uh60.png` 同时用于 UH-1Y / UH-60M / OH-6 / 渡鸦
    - `us_m1151.png` 同时用于 M1151 / M1117 / 改装皮卡
    - CAF 的豹 2A6M 有一处用了 `uk_challenger2.png`
  - 结论：图片不是「个别错」，而是**系统性缺图 + 借用**，需要按型号重建映射。

## 2. 需求一：大图标 + 分阵营 + 悬停详情

### 2.1 布局

- 默认（也是唯一主视图）：**按阵营分块**
  - 每个阵营：旗帜 + 阵营名 + 简介一行
  - 阵营内再按类别分组（坦克 / 步战 / 装甲运兵 / 侦察突击 / 运输补给 / 直升机 / 火炮）
  - 每个载具是一张「大图标卡片」：图标显示区约 **120×90px**（可按屏幕放大到 140×105）
- 保留顶部：搜索、类别筛选、阵营快捷筛选
- 「按载具」表格视图：建议移除（信息密度低且与"分阵营"冲突）；如要保留，改为可选的高级视图

### 2.2 数量展示

按需求去掉：
- 载具卡片上的 `×N`
- 阵营标题里的「共 X 台」
- 页头的「🏁 共 X 台」
- 排序里的「总台数 ↓」

保留（这些不是"载具数量"）：
- 阵营数、编制数、型号数
- 类别下的「N 型号」

### 2.3 悬停大图 + 信息

- 桌面：鼠标进入图标 **120ms** 后弹出浮层
  - 大图：约 360×240，使用 512px 原图，`object-fit: contain`
  - 信息：名称、阵营、类别、类型、乘员、武器列表（含弹药）、票数/复活（次要信息）、备注
- 浮层用 `Teleport` 挂到 body，跟随图标定位，靠近视口边缘自动翻转，避免被父容器裁切
- 移出图标/浮层 150ms 后关闭；悬停浮层本身不关闭（方便看长信息）
- 移动端：没有 hover → 点击图标弹出底部抽屉（大图 + 信息）
- 键盘：卡片可 Tab 聚焦，Enter 打开同样的信息面板
- 性能：图标 `loading="lazy"`；hover 时才预加载 512px 大图；同一张大图全站缓存

### 2.4 预估

- UI 改造：1～1.5 天（含移动端与无头断言）

## 3. 需求二：补全载具武器 / 弹药数据

### 3.1 数据源

直接访问 `squad.fandom.com` 在本机/服务器都被网络拦截，但已验证可通过 **AllOrigins 代理**访问 MediaWiki API：

- 车辆分类：`Category:Vehicles` 共 **134 个页面**（已实测返回）
- 单页 wikitext 可取到，例如 M1A1：
  - 120mm M256：21 发 AP + 21 发 HEAT
  - 同轴机枪：2000 发
  - 40mm 烟雾发射器：2 发
  - 乘员、载具类型等

> 备用：Squad Wiki 的 GitHub 数据管线（目前只有武器数据、版本 7.0），可用于武器名称/弹匣口径交叉校验，不作为车辆挂载依据。

### 3.2 数据结构（新增 `frontend/src/data/squad/vehicle-specs.js`）

```js
{
  key: 'M1A1',                 // 规范型号
  aliases: ['M1A1', 'M1A1 AIM SA'],
  displayName: 'M1A1',
  class: '主战坦克',
  crew: 3,
  seats: 4,
  armaments: [
    { name: '120mm M256 滑膛炮', type: 'main_gun', ammo: 42,
      detail: '21 AP / 21 HEAT', reload: '6s' },
    { name: 'M240C 同轴机枪', type: 'coax', ammo: 2000 },
    { name: '40mm 烟雾发射器', type: 'smoke', ammo: 2 }
  ],
  source: 'https://squad.fandom.com/wiki/M1A1',
  sourceRevision: '2026-xx-xx',
  gameVersion: '10.6.2'
}
```

- `vehicle-stats.js` 里已有 `vehicleKey()`，就在这里接「名称 → 规范型号」别名表
- 262 个名称预计归并为 **约 150 个真实型号**；同车族不同武器站（M1151 M2/M240/Mk19）保留为独立变体，但共用车身图

### 3.3 采集与校验流程

1. 拉 `Category:Vehicles` 全部页面（134）
2. 批量取 wikitext，解析：
   - infobox 的 `image`
   - Gameplay/General Information 里的武器、弹药、乘员、烟幕
3. 生成 `tmp_work/vehicle-specs.raw.json` + 人工核对表
4. 对无法确认的字段一律写 `null` 并标注「待核对」，不猜
5. 校验脚本：
   - 每个战斗载具至少 1 个 weapon
   - `ammo` 为正整数或 null
   - 每个 spec 必须有 source
   - 262 个名称 100% 能映射到 spec 或有明确 fallback

### 3.4 预估

- 采集脚本 + 首轮解析：1 天
- 人工核对 134 页（重点核对弹药与同车族差异）：1～2 天
- 合并进前端 + 校验：0.5 天

## 4. 需求三：载具图片核对与替换

### 4.1 审计

- 以 262 个名称 → 现有 `icon_url` 生成审计表：
  - 正确（同型号车身图）
  - 车族通用（同底盘可接受，如 M1151 不同武器站）
  - 错误（跨型号、跨阵营）
  - 缺失
- 自动标红：同一图片被 ≥3 个不同车族共用、文件名与型号明显不符
- 产出一份 CSV/HTML 对照表，先给用户过目，不直接替换

### 4.2 取图

- 从 Wiki 页面 infobox 的 `image = xxx.jpeg` 取原图（MediaWiki `imageinfo` 接口，仍走 AllOrigins）
- 选图标准（按你的要求）：
  - 优先**车身侧面/前 3/4 视角**的完整车辆图
  - 不用驾驶舱、炮塔特写、剪影、图标、旗帜
  - 背景尽量干净；同阵营尽量统一风格
- 统一处理：最长边 512px、WebP（或保留 PNG 透明底）、命名 `<阵营>_<型号>.webp`
- 同一底盘不同武器站：允许共用车身图，但在浮层里用文字标明武器站差异

### 4.3 审核

- 生成「按阵营 contact sheet」：一页看完全部图 + 名称，方便你逐张确认
- 你确认后再替换 `public/squad-assets/vehicles` 与 `icon_url`
- 版权说明：图片来自 Squad Wiki / 游戏素材，站点为玩家社区；建议在页脚或页面底部加「载具图片来源于 Squad Wiki」的致谢

### 4.4 预估

- 审计表：0.5 天
- 下载 + 统一处理 + 人工筛选：1～1.5 天
- 前端接入 + 校验：0.5 天
