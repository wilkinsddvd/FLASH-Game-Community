## 1. 标签体系

### 1.1 每个载具最多两个标签

| 标签 | 规则 | 例子 |
|---|---|---|
| 阵营标签 | 必填，来自所属阵营 | `USMC`、`PLA`、`WPMC` |
| 类别标签 | 能准确归入下面 15 类之一时显示 | `坦克`、`非装甲轮式运兵车`、`复活车` |

- 卡片：最多 2 个 chip
- 浮层：阵营 + 类别；原始 `type` 作为普通文字展示，不算标签
- 不做角色/变体/专属/通用标签

- 「未分类」是筛选项，不是标签

### 1.3 票数/复活：按编制展示，不做众数

现状问题：
- `vehicle-stats.js` 的 `summarize()` 对票数/复活取「出现次数最多的值」
- 同一阵营同一载具在不同编制里票数/复活不同时，会只显示一个众数，信息被抹平

新规则：
- 每个阵营的每张载具卡片保留 **该阵营下所有编制的原始条目**
- **卡片上**：
  - 所有编制票数一致 → 显示 `票数 5`
  - 票数不一致 → 逐条列出「编制 + 票数」，例如：
    `第一骑兵团 票数：5`、`第2斯崔克骑兵旅 票数：10`
  - 不显示数量；不使用 `*` 或众数
- **悬停/抽屉**里用表格列出完整值：

| 编制 | 票数 | 复活 | 初始延迟 |
|---|---|---|---|
| 第三轻装甲侦察营 | 5 | 6:00 | 4:00 |
| 第1坦克营 | 10 | 10:00 | 9:00 |

- 跨阵营共享载具（如 M1151）在各阵营卡片里只显示**该阵营**的编制行，不混入其他阵营的票数
- 数量 `count` 不展示，但内部保留

> 你举的例子「美国陆军第一骑兵团 M1151 M2 票数：5」：当前编制数据里第 1 骑兵团没有 M1151 M2（USA 的 M1151 M2 只出现在第 504 空降步兵团 / 第 497 战斗支援营，票数都是 5）。方案按你要的格式展示；编制数据核对阶段会把这类缺项一并修正。

**WPMC 复活车**：
- `M113A3 机动支援载具` 在 wpmc-light / wpmc-airassault / wpmc-combined 三个编制里票数都是 **20**
- 卡片合并为 1 张，显示 `票数 20`；三个条目全部覆盖为 `复活车` 标签
- 悬停表仍列 3 行（编制不同，票数同为 20）

### 1.4 其他易混边界

- M1151 / M-ATV 普通武器型 → `侦察车`
- M1151 / M-ATV 陶式等反坦克导弹型 → `火力支援车`
- 改装皮卡 M2/M134 → `火力支援车`；纯运输皮卡 → `非装甲轮式运兵车`
- 运兵卡车/运输型 → `非装甲轮式运兵车`；补给卡车 → `补给载具`
- M1064A3 迫击炮车、BM-21 → `火力支援车`
- M1128、ZLT05、2S25 → `突击炮`
- 四轮摩托/ATV → `摩托`
- 所有橡皮艇 → `橡皮艇`
- WPMC `M113A3 机动支援载具` → `复活车`；其他 M113A3 → `履带式装甲运兵车`

- 阵营内按类别分组，顺序按上表；「未分类」最后

  - 一致：`票数 5`
  - 不一致：按编制逐行列出 `编制简称 票数：X`（完整编制名放浮层）
- 无数量、无台数、无「按载具」按钮

### 2.2 悬停浮层（桌面）

- 进入 120ms 弹出，离开 150ms 关闭
- 内容：
  - 360×240 大图
  - 名称、阵营 chip、类别 chip
  - 原始类型文字
  - **武器列表**：武器名 / 口径 / 弹药数
  - **票数/复活表**：按该阵营下所有包含该载具的编制逐行列出（编制全名 + 票数 + 复活 + 初始延迟）
  - 备注
- Teleport + 视口边缘翻转
- hover 时才预加载 512px 大图

### 2.3 移动端

- 点击卡片弹底部抽屉，内容同浮层；票数表可横向滚动/换行

### 2.4 筛选

- 搜索：名称 / 类型 / 阵营 / 武器名
- 类别筛选：15 类 + 未分类 + 全部
- 阵营快捷筛选保留
